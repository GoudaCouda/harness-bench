The previous operator attempted to retire the old anchor, but the protected controller rejected the transition. Recover from the recorded state without rolling back already-rotated servers or bypassing the trust gates.

Work only inside `$WORKSPACE`; the scenario is completely offline. Treat `evidence/`, `policy/`, `ca_lib.py`, and `cactl.py` as immutable. You may modify only the declared state files through `cactl.py` and create the declared `work/` artifacts.

Begin with the tool's help, status, history, and component inspection commands. The controller provides bounded commands for repairing the controller-manager CA-file roles, refreshing a named client's trust, rotating one named server leaf, running a trust-mode verification, and retiring the old anchor. Read the official-workflow constraints encoded in `policy/rotation_policy.json`; do not infer safety from aggregate counts alone.

Before mutating state, create `work/rotation_plan.json` containing:

- `cluster_id` and `policy_version`;
- an ordered `steps` array whose rows contain `order`, `action`, `target`, `from`, `to`, `prerequisites`, and `evidence`;
- `rollback_boundary` explaining which already-completed signer changes must not be reversed;
- `retirement_gate` listing the conditions that must be proven before the old anchor can be removed.

Then use `python3 cactl.py ...` to complete the legal recovery. Required operational evidence includes:

- `work/dual_probe.json`, generated by a complete dual-trust verification before retirement;
- `work/verification.json`, generated by final new-only verification;
- append-only `state/rotation_events.jsonl` preserving every original event as an exact prefix;
- final `state/rotation_state.json` with no old-only trust or old-signed required endpoint.

Run the final new-only verification a second time and confirm that the state, event log, and verification bytes do not change.

Write `work/rotation_handoff.md` describing the bundle-role failure, lagging client, remaining old-signed server, legal sequence, dual-probe evidence, old-anchor retirement, final new-only proof, transient reconnect expectation, rollback boundary, and next monitoring steps. State explicitly that this was an offline synthetic recovery: no production cluster was changed and no external action or communication occurred.

Do not edit JSON state directly, delete or rewrite history, treat a CA bundle as a single signing CA, remove old trust before a complete dual probe, fabricate probe rows, or claim that production changes were executed.
