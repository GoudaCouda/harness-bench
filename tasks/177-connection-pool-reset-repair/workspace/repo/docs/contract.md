# Repair connection-pool reset and fair reuse contract

Replay pool operations by at/id. Checkout leases the lexical idle connection, otherwise creates a deterministic new connection below capacity, otherwise queues FIFO. Release requires matching lease owner: a known connection in the wrong state or owned by another client emits `ownership_block`; an unknown connection id raises `ValueError`. Clean release returns idle and dirty release quarantines. Reset of a known non-quarantined connection emits `reset_not_needed`; quarantine reset success increments generation and returns idle, while failure closes it. After every operation, idle connections serve queued clients FIFO and emit dequeue actions. Closed connections do not consume capacity. Initial non-closed connections must not exceed capacity; a leased connection must have a non-empty owner and every other state must have no owner. Checkout/release clients and operation-specific boolean `clean`/`success` fields are required. Return action history, remaining queued operation ids, and final sorted connections. Duplicate operation/connection ids and malformed state raise `ValueError`.

The output object has exactly `actions,queue,connections`. Every action has exactly `id,action,connection`; action is one of `leased,created,queued,ownership_block,released,quarantined,reset_not_needed,reset,closed,leased_from_queue`. New ids are the first unused `new-N` from N=0 upward. A dequeue action id is the queued operation id plus `:dequeue`. Queue contains remaining checkout operation ids. Each id-sorted connection has exactly `id,generation,state,owner`.

The function must not mutate inputs. Run `python3 -m unittest discover -s tests -v` and `python3 bin/run_repair.py`, re-open `out/result.json`, and document verification evidence plus the offline boundary in `REPAIR_NOTES.md`.
